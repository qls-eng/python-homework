# 课堂笔记：`if __name__ == '__main__':` 的含义与作用

## 一、它是什么

每个 Python 模块（`.py` 文件）在被解释器加载时，都会自动生成一个内置变量 `__name__`：

- **当这个文件被直接运行**（`python xxx.py`）时，Python 把它的 `__name__` 赋值为字符串 `'__main__'`；
- **当这个文件被别的文件 `import` 导入**时，`__name__` 被赋值为模块名（也就是去掉 `.py` 的文件名）。

所以这行判断的意思是：**只有当前文件是被直接运行时，才执行下面缩进的代码；被导入时不执行。**

```python
if __name__ == '__main__':
    main()
```

## 二、为什么要这么写（why）

### 1. 区分"直接运行"和"被导入"两种身份

同一个 `.py` 文件有两种使用方式：

- 作为**主程序**直接运行；
- 作为**工具模块**被其他文件 `import`，复用里面定义的函数、类。

如果把执行语句直接写在文件顶层，那么一旦被 `import`，这些语句就会立刻执行一遍——这往往不是我们想要的。加上 `if __name__ == '__main__'` 之后，测试、演示、启动代码只在直接运行时触发，被导入时安静地只提供函数定义。

### 2. 让模块可以被复用，而不产生副作用

举例，一个工具模块 `math_utils.py`：

```python
def add(a, b):
    return a + b

# 不加判断时，被 import 就会立刻打印，产生副作用
# print("模块被加载了")

if __name__ == '__main__':
    # 只有直接运行本文件时才做自测 / 演示
    print(add(1, 2))
```

别的文件 `import math_utils` 时，不会执行 `print(add(1, 2))`；而直接 `python math_utils.py` 时才会执行自测代码。

### 3. 方便单元测试和模块化拆分

把"对外提供的函数/类"写在判断之外，把"程序入口、自测代码"写在判断之内，模块既能独立运行，也能被别的程序干净地引用，这是 Python 工程的标准写法。

## 三、一个完整示例

```python
# greet.py

def greet(name: str) -> str:
    return f"你好，{name}！"


if __name__ == '__main__':
    # 直接运行本文件时的自测代码
    print(greet("同学"))
```

- 直接运行 `python greet.py`：`__name__ == '__main__'` 成立，输出 `你好，同学！`
- 其他文件 `import greet`：`__name__ == 'greet'`，判断不成立，只加载 `greet` 函数，不打印任何内容。

## 四、要点小结

| 场景 | `__name__` 的值 | `if __name__ == '__main__'` 是否成立 |
|------|-----------------|--------------------------------------|
| 直接运行 `python xxx.py` | `'__main__'` | 成立，执行下方代码 |
| 被 `import xxx` 导入 | 模块名 `'xxx'` | 不成立，跳过下方代码 |

一句话总结：**`if __name__ == '__main__':` 是程序的"入口开关"，用来区分本文件是被直接执行还是被当作模块导入，避免被导入时自动执行测试或启动代码。**
